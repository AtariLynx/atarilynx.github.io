## Mikey boot process

Mikey can have its memory range of `$FE00` to `FEF8` mapped to internal ROM. This ROM contains the startup code for the Atari Lynx. The startup vector for the Lynx is hardcoded to be `$FF80` inside the boot ROM code. The ROM will perform a number of steps to start and initialize the Lynx and load a cartridge and start the program or game that is on it.

1. **Turn cartridge power off**
1. **Erase RAM memory** to zeros (`0x00`)
1. **Initialize Mikey** (see table below)
   Effectively it sets the timers for horizontal and vertical scans, and loads the palette with black and yellow
1. Copies decryption algorithm from ROM to RAM  
   256 bytes of code are copied into RAM, because the algorithm uses self-modifying code. This cannot be done in ROM. Located at `$FEC1` and moved to `$5000`
1. Perform decryption process of cartridge header frame containing loader
1. Execute loader at `$0200`

If during the boot process there turns out to be something wrong with the bootloader or cartridge contents, the Lynx will not start up correctly. It will either freeze or display an "INSERT GAME" message on screen.

## Encryption process

The example uses the files from the Mandelbrot sample in the `6502/examples` folder. We will build a 128KB rom file with encryption that is able to run on real hardware.

```shell
ASSIGN 6502: AmigaHD:6502
ASSIGN HANDY: AmigaHD:Handy
PATH HANDY: ADD
```

The first step is to compile the source coude `mandel.src` to a binary object file.

```shell
asm mandel.src +R +H30000 +L +S
asmstrip mandel.bin
```

There should be three new files now:

- `mandel.bin`
- `mandel.lst`
- `mandel.sym`
- `mandel.raw`

The `mandel.hsf` file contains the directory layout of files contained in the cartridge. It references `cartdefs.i` that defines details about the cartridge to create.

```
* Test file for HandyROM
* Created by RJ Mical
* 26 April 1989

	.IN cartdefs.i

	FILE TITLE_FILE
	BIN title1.bin

	FILE MAIN_FILE
	BIN mandel.bin
```

The `HandyROM` tool uses `.hsf` files to create a binary file with the `.rom` extension that has a reserved space of 410 bytes (filled with zeros `0x00`) for the encrypted header. The header will be created in the next step and is going to replace the zeros eventually.

In the next step the AmigaDOS script `doit` is executed from the shell window. It requires two arguments. One is the name of the ROM file and the other the size of the ROM to create. Since the `cartdefs.i` file specifies the romsize, it should use the same size now.

```shell
execute doit mandel.rom 128
```

The script performs a number of steps:

1. Checks whether file specified exists
1. Checks that ROM size is either `128`, `256` or `512`
1. Creates file `romsize.i`
1. Runs `buildchk` to check the presence of two directory entries. It creates several files (`romdir.i`, `romsize.i` and `checkstring.src`).  
1. Compilation of the boot loader code in `boot.src` with references to the files created in the previous step. The result will be two files `boot.bin` and `boot2.bin` for the two stages of the boot loading process. 
1. Strips the first and last bytes of the boot code binaries. This results in raw binary files `boot.raw` and `boot2.raw`, without metadata of the load address and length.
1. Obfuscates the raw binary files and writes these to `input1` and `input 2`.
