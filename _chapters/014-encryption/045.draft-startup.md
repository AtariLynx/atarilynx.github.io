The Atari Lynx has a hardcoded bootup procedure involving initialization of the hardware and decryption followed by deobfuscation of the header of the inserted cartridge. The boot sequence is important as it cannot be altered until the execution is rendered to the boot loader. Also, the code only initializes the Mikey chip, so any loader should perform the initialization of Suzy. In this chapter the boot sequence is explained in detail. The encryption process and headers are described in other chapters.

## Mikey boot process

The ROM area of Mikey contains the startup code for the Atari Lynx at `$FF00` to `$FFF8`. The startup vector for the Lynx is hardcoded to be `$FF80` inside the boot ROM code. The ROM will perform a number of steps to start and initialize the Lynx and load a cartridge and start the program or game that is on it.

1. **Turn cartridge power off**
1. **Erase RAM memory** to zeros (`0x00`)
1. **Initialize Mikey and Suzy** (see table below)
   Effectively it sets the timers for horizontal and vertical scans, and loads the palette with black and yellow
1. **Copy decryption algorithm** from ROM to RAM  
   256 bytes of code are copied into RAM, because the algorithm uses self-modifying code. This cannot be done in ROM. The code is located at `$FEC1` in ROM and moved to the RAM address `$5000`
1. **Perform decryption** process of cartridge header frame containing loader.  
   The process for decryption is a reverse of encryption. More information on encryption can be found in the corresponding chapter
1. **Execute decrypted loader** located at `$0200`

## Decryption process

sadas

   1. Sets destination address to `$0200`
   1. Preparing reading from cartridge
   1. Load first byte of frame from cartridge to determine number of blocks
   1. Decrypt all blocks in frame into `$0200` an onwards
   1. Jump to start at `$0200`



If during the boot process there turns out to be something wrong with the bootloader or cartridge contents, the Lynx will not start up correctly. It will either freeze or display an "INSERT GAME" message on screen.

![debugbreak](../../assets/chapters/insertgame.png)
![debugbreak](../../assets/chapters/insertgame2.png)

You can see that the yellow and black color are used to display the text of the message.

- Cartridge not inserted: Static `INSERT GAME` displayed
- Decryption failure: fast flashing `INSERT GAME`
- Hash value mismatch of cartridge contents: Lynx freezes
