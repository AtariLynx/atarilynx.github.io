## BRK routine

The 6502 family processors have a special sequence to handle user breaks. The processor will perform the following sequence whenever a break, indicated by opcode `00`, is encountered during execution:

1. Increase program counter `PC` with **two** to skip `BRK` and next byte
1. Push high byte of `PC`
1. Push low byte of `PC`
1. Push the processor status (`PS`) to stack **with the `B` flag set**

Given that the stack will grow upward to lower memory locations, starting at `$01ff`, the stack will look as follows after the sequence:

```asm
$0100   stack limit
...
$01fa   <- SP points here, just above top of used stack
$01fb   PS
$01fc   PCLo
$01fd   PCHi
...
$01ff   bottom of stack
```

> ### Important
>
> Note that `B` is only set on this copy of the status flags.  
{: .block-warning}

When the current processor status is evaluated by reading `PS` it will never have the `B` flag set. Therefore, it is not possible to determine the reason for a jump to the vector `IRQVEC` at `$FFFE-$FFFF`of by inspecting `PS`. Instead you should retrieve the value from the stack and test for bit `40` there. This will allow you to see whether the vector jump was caused by and interrupt or BRK instruction.

One approach to inspect the B flag on the stack is to use the following code:

```asm
PLA         ; load status register
PHA         ; Restore onto stack again
AND #$10    ; Isolate B flag
BNE break   ; Branch to `break` routine
; Normal interrupt processeing
...
```

As we will see later this approach does not always work when debugging.

## BLL IRQ handler

The BLL handler routine for interrupts includes a small leading logic block.

```asm
irq::
    PHX
    PHA
    LDX #0
    LDA INTSET
IFD BRKuser
    BEQ .break
ENDIF
    ; Normal IRQ handling

.break
    ; BRK handling
```

First the `X` and `A` registers are pushed onto the stack. It is important to immediately store these, so the values do not get lost. This is particularly important for the debugging features as it relies on manipulating A and X, while later restoring these before resuming execution.

This hardware register `INTSET` at `$FD81` holds a byte with 8 bit flags representing the eight timers from timer 7 to timer 0 (left to right). Each timer that causes an interrupt will be indicated by that bit flag set.

When the debugging and BRK functionality has been turned on by setting the `BRKuser` value to 1, the logic includes a branch to a dedicated section for BRK handling. This branch is taken when there are no bits set in `INTSET`, meaning that there was no interrupt, implying that a `BRK` instruction must have caused a jump to `IRQVEC`.

The `.break` branch has the rest of the logic for a BRK command.
```asm
 IFD BRKuser
.break
    TSX
    LDA $103,x      ; Fetch PS register from stack
    BIT #$10        ; BRK triggered?
    BEQ dummy_irq   ; Safe exit should B flag not be present
    PLA             ; Restore A and X from stack
    PLX
    JMP (BRKvec)    ; Jump to special BRK vector set by InitBRK
 ENDIF
```

You can see how this handling is only available for `BRKuser`. The logic fetches the current stack pointer into the `X` register. The offset `SP` into the stack is pointing at the next to use value, one above the last stack position used. We also need to account for the fact that both `A` and `X` were stored after the BRK processor sequence. The offset is increased by three bytes using `LDA $103,x`.

For example, the stack might look like this when a `BRK` instruction was handled and the first part of the IRQ/BRK vector handler has already executed. The stack pointer will be `#$f8` pointing to just above the top of the stack.

```
$0100   stack limit
...
$01f8   <- SP points here
$01f9   A
$01fa   X
$01fb   PS
$01fc   PCLo
$01fd   PCHi
...
$01ff   bottom of stack
```

The accumulator now holds the `PS` value and is checked for the BRK bit flag. It should be present, because there were no bits set for interrupts and still the IRQ vector was used. Just to be on the safe side, a graceful exit via `dummy_irq` is taken when the `B` flag is not set.

Finally, the accumulator and X register are restored and a jump to address found in the zeropage `BRKvec` location is made. When `INITBRK` was used, the `BRKVec` value is set to the `EnterBRK` routine that prepares the call to the break server.

The normal IRQ handling checks for the serial interrupt separately from the rest of the interrupts. This gives the serial the highest priority over the others.

```asm
    BIT #$10    ; SERIAL IRQ
    BEQ .1
    JMP (irq_vecs+8)    ; Jump to SerialIRQ routine

.loop
    INX
    INX
.1
    LSR
    BCC .loop

    LDA mask,x
    STA INTRST
    JMP (irq_vecs,x)

; Break implementation 

mask
    dc.w $01,$02,$04,$08,$10,$20,$40,$80
```

The logic check for the presence of the 4th bit (`#$10`) in the accumulator that currently holds the value found in `INTSET`. If present, it shortcuts the rest of the logic by immediately jumping to the interrupt handler at the 4th position in the jump table (which has the address of the serial IRQ handler).

If the serial interrupt bit is not present, it loops through the `INTSET` value looking for the first bit that is set, right to left. It shifts the value to the right and checks if the bit has been pushed into the carry flag. If so, the particular interrupt bit is reset by using the `mask` value at that position. The mask holds the exact bit required to reset the IRQ flag. It is written to the IRQ reset handware register `INTRST` located at `$FD80`. The last action is to jump to the IRQ handler routine found at the current `X` offset in the jump table.

## Break server

The subroutine `InitBRK` is responsible for the initialization of the break server. It will copy the break server logic from regular memory (as part of the program) into high memory at $FE40 and onwards.


## Interrupts

There are two macros to help you with the handling of interrupts and preparing the interrupt jump table: `SETIRQ` and `SETIRQVEC`. 

As you know, Mikey has 8 interrupts, all generated by the respective timers 0 through 7. THe timers 0, 2 and 4 are special as they are used for horizontal screen timing, vertical blank time and serial interrupts.

The macro `SETIRQVEC` is used to store the location of a IRQ handler routine for an IRQ associated with a particular timer. 

```
SETIRQVEC {IRQnumber},{handler_address}
```
where `IRQnumber` is a number between 0 and 7 for the timer and its IRQ, and `handler_address` is the label or hardcoded address of the handler routine.

```asm
SETIRQVEC 0,HBL
SETIRQVEC 2,VBL
SETIRQVEC 4,SerialIRQ
SETIRQVEC 7,timer7
```
