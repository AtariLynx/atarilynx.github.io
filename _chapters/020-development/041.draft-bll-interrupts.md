A common technique for handling interrupts in 6502 and related processors is to have centralized logic that takes care of determining with routine should handle a particular interrupt. This central logic is executed whenever an interrupt occurs and the IRQVEC interrupt vector of the processor is used to jump to it.

The central logic often uses a table with addresses corresponding to the various handlers per interrupt. The interrupts in the Lynx are numbered from 0 to 7, and are always timer related. 

## Including interrupt support

- Allocate memory for a jump table
- Initialize table entries to meaningful defaults
- Install your handlers for specific interrupts

Your BLL program will need three files for macros, variables and implementation to include interrupt support.

```6502
; Initialization of your program
include <macros/irq.mac>
include <vardefs/irq.var>

; Rest of your program

; Includes of library functions
include <includes/irq.inc>
```

When you use the INITIRQ macro like this, it will expand to the following:

```6502
    irq_vecs    equ irq_vectors
    jsr InitIRQ
```


## IRQ Jump table

BLL uses a table to store 
Before the start of your code you have to allocate memory for the IRQ jump table that the BLL library functions for interrupt handlers expect.

```6502
BEGIN_MEM
; Define array to hold 8 (double-byte) address entries 
irq_vectors     ds 16
END_MEM

Start::
; 
    INITIRQ irq_vectors
```

The routine InitIRQ will initialize the jump table to point to a dummy interrupt handler called `dummy_irq`. The implementation for this handler simply returns without doing any actual work besides the required cleanup.

```6502
dummy_irq
	END_IRQ
```

The normal IRQ handling checks for the serial interrupt separately from the rest of the interrupts. This gives the serial the highest priority over the others.

```6502
irq::
    phx
    pha
    ldx #0
    lda $fd81
    bit #$10    ; SERIAL IRQ
    beq .1
    jmp (irq_vecs+8)    ; Jump to SerialIRQ routine

.loop
    inx
    inx
.1
    lsr
    bcc .loop

    lda mask,x
    sta INTRST
    jmp (irq_vecs,x)

; Break implementation (only when debugging is included)

mask
    dc.w $01,$02,$04,$08,$10,$20,$40,$80
```

The logic check for the presence of the 4th bit (`#$10`) in the accumulator that currently holds the value found in `INTSET`. If present, it shortcuts the rest of the logic by immediately jumping to the interrupt handler at the 4th position in the jump table (which has the address of the serial IRQ handler).

If the serial interrupt bit is not present, it loops through the `INTSET` value looking for the first bit that is set, right to left. It shifts the value to the right and checks if the bit has been pushed into the carry flag. If so, the particular interrupt bit is reset by using the `mask` value at that position. The mask holds the exact bit required to reset the IRQ flag. It is written to the IRQ reset handware register `INTRST` located at `$FD80`. The last action is to jump to the IRQ handler routine found at the current `X` offset in the jump table.

## Interrupt handler routines

An interrupt that is triggered can have a handler routine to react to the event causing the trigger. Typically, this will be interrupts from timer 0 and 2 for horizontal and vertical video blank interrupts, or timer 4 for serial input/output being available for reading or writing. An IRQ is not required to have a handler. The interrupt base infrastructure will take care of clearing the interrupt flags in `INTRST`.

A handler routine should follow a certain structure. It must always end with an `rti` (**R**eturn **F**rom **I**nterrupt) instruction to return from the interrupt sequence. As the interrupt sequence of 6502 family processors pushes certain items on the stack, you should make sure these are removed to avoid unwanted growth of the stack. You can pop the values of A and X from the stack to clean it up and either use or discard them. In BLL you will need to include the instructions for `pla` and `plx` yourself.

```6502
; Interrupt handler routine
HBL::

; Your logic

  pla
  plx
  rti
```

## Connecting handlers to IRQs

There are two macros to help you with the handling of interrupts and preparing the interrupt jump table: `SETIRQ` and `SETIRQVEC`.

The macro `SETIRQVEC` is used to store the location of a IRQ handler routine for an IRQ associated with a particular timer and its interrupt.

```6502
SETIRQVEC {IRQnumber},{handler_address}
```

where `IRQnumber` is a number between 0 and 7 for the timer and its IRQ, and `handler_address` is the label or hardcoded address of the handler routine, such as `VBL` in the example shown earlier.

```asm
SETIRQVEC 0,HBL
SETIRQVEC 2,VBL
SETIRQVEC 4,SerialIRQ
SETIRQVEC 7,timer7
```
